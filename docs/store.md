# Правила работы со Store

Store хранит только глобальные данные приложения. Его ответственность ограничена хранением, чтением и записью значений. Task определяет, какие данные записать по правилам бизнес-сценария. Presenter готовит прочитанные данные для отображения.

## Хранить минимум данных

Перед добавлением значения определите его источник истины. Храните в Store только исходные данные, за которые он отвечает. Производные значения вычисляйте из исходных. Например, запрос, жанр и номер страницы поиска уже хранятся в URL. Presenter читает их оттуда. Состояние, которое нужно только одному экрану на время его работы, оставляйте в Presenter.

## Сокращать лишние обращения

- Presenter подписывается только на ту часть состояния, которая нужна его View.
- Для синхронного действия Task читает нужные значения один раз и использует их в расчётах. После `await` прочитайте состояние повторно, если дальнейшее решение зависит от актуального значения.
- Если несколько изменений вместе образуют один результат, применяйте их одной операцией Store. Тогда подписчики сразу увидят согласованное состояние.

При ревью проверьте, потребует ли новое значение синхронизации с другим источником и можно ли убрать чтение, подписку или запись, сохранив актуальность и согласованность данных.
