# Архитектура проекта

## Стек

- React
- TypeScript в режиме strict
- CSS Modules

## Слои

View отображает данные и передаёт события в Presenter. Presenter готовит данные для View и вызывает Tasks для выполнения бизнес-действий. Tasks взаимодействуют со сторами напрямую.

### View и Presenter

- **View** — файл компонента с JSX.
- **Presenter** — логика представления компонента (без JSX). Оформляется как хук `use<Name>`. Бизнес-логика выносится в слой Tasks.
- Presenter создаётся, только если у компонента есть логика. Компонент, который только раскладывает пропсы в JSX, хука не имеет.
- **Логика** — всё, что вычисляет или меняет данные, а не просто выводит их:
  - хуки React: состояние, эффекты, ref, контекст, мемоизация;
  - обработчики событий и другие функции, объявленные в компоненте (кроме render-функций, см. ниже);
  - вычисления над данными: фильтрация, сортировка, форматирование, сборка строк, производные флаги (`isVisible`, `hasList`).
- **Не логика** (остаётся во View):
  - передача пропсов и значений из Presenter в разметку;
  - условный рендер и `.map` по уже готовым флагам и массивам;
  - сборка классов через `clsx` и простые выражения в атрибутах по готовому значению (`aria-current={item.isCurrent ? 'page' : undefined}`);
  - render-функции внутри компонента, которые только выбирают и возвращают JSX по готовым флагам, например:
    ```tsx
    const renderContent = () => {
        if (isLoading) {
            return <Loader />;
        }

        return <List items={items} />;
    };
    ```
- Presenter всегда оформляется как хук `use<Name>`, даже если внутри нет хуков React (только вычисления и обработчики). Это сделано намеренно: у всех компонентов единый контракт, и когда появятся состояние или эффекты, не придётся менять ни имя, ни View. Presenter вызывается на верхнем уровне компонента, как любой хук.
- Presenter принимает `props: Props`: у него тот же интерфейс, что у компонента.
- Компонент передаёт в Presenter `props` целиком: `use<Name>(props)`. Пропсы, которые Presenter не использует (например, `className` или `children`), он просто не деструктурирует. Если Presenter не использует ни одного пропса, он не принимает параметров и не импортирует `Props`, а компонент вызывает его без аргументов: `use<Name>()`.
- Presenter вызывает Tasks в ответ на события интерфейса и обрабатывает результаты их выполнения. Локальные состояния загрузки и ошибки, а также навигация после выполнения задачи относятся к Presenter.

### Tasks

**Tasks** — слой бизнес-логики приложения.

**Task** — обычная JavaScript-функция, написанная на TypeScript, которая реализует конкретный вариант использования: найти сериалы, авторизоваться или выйти из аккаунта. В терминах архитектуры Task — это **Interactor**.

Имя Task обозначает действие и начинается с глагола, например `searchShows`, `filterShowsByGenre` или `logout`. Task может быть асинхронной и возвращать результат, который Presenter ожидает и обрабатывает как результат обычной функции.

Task не зависит от React: не использует React-хуки, контекст и другие механизмы слоя отображения. При смене библиотеки отображения бизнес-логика должна сохраняться, а View и Presenter могут измениться.

Task может использовать внешние библиотеки и API текущего окружения, например `fetch`, `AbortController` и `AbortSignal`. Общего запрета на такие зависимости нет.

Для уменьшения зависимости от конкретных инструментов рекомендуется выделять внутренние функции приложения, скрывающие детали реализации за понятным интерфейсом. Например, задача может вызывать функцию поиска сериалов, которая формирует и отправляет HTTP-запрос. Такие обёртки не обязательны; Task может импортировать их напрямую или получать зависимости через аргументы.

Со сторами Task взаимодействует напрямую: может импортировать экземпляр стора и вызывать его методы чтения и обновления состояния. Для этого не используются React-хуки и посредники вроде Redux Thunk или Redux Saga. Task остаётся обычной JavaScript-функцией.

## Структура проекта

- View компонента `Name` лежит в одноимённой папке: `Name/Name.tsx`.
- Интерфейс, типизирующий пропсы компонента, называется `Props` и экспортируется из файла `Name/types.ts` рядом с компонентом. Там же лежат другие типы, относящиеся к компоненту (например, тип элемента списка, который компонент принимает в пропсах).
- Компонент импортирует `Props` из `./types`, а Presenter — из `../types`.
- Файл `types.ts` создаётся при наличии пропсов или других типов, относящихся к компоненту и его поддереву. Если таких типов нет, файл не создаётся.
- Стили компонента лежат в той же папке в файле `Name/Name.module.css`.
- Presenter лежит в `Name/logic/use<Name>.ts`, а локальные задачи — в `Name/logic/tasks/`. Папка `logic` создаётся при наличии логики, папка `tasks` — при наличии локальных задач.
- Одна задача представляет собой действие и лежит в отдельном файле или папке с названием задачи, например `searchShows.ts` или `searchShows/`.
- Переиспользуемые задачи лежат в глобальной папке `src/tasks/`.
- Если компонент A зависит от компонента B, то B лежит в папке A: `A/B/B.tsx`.
- Переиспользуемые компоненты лежат в папках `components/`. Уровень вложенности такой папки определяется местами использования компонента: компоненты ниже по дереву его используют, компоненты выше по дереву — нет. То есть папка `components/` создаётся в ближайшем общем предке всех мест использования.

Пример структуры компонента (необязательные части создаются по мере необходимости):

```text
Name/
├── Name.tsx
├── Name.module.css
├── types.ts
├── logic/
│   ├── useName.ts
│   └── tasks/
│       └── performAction.ts
├── Child/
│   └── Child.tsx
└── components/
    └── Shared/
        └── Shared.tsx
```

В этом примере `Child` используется только компонентом `Name`, а `Shared` — компонентами `Name` и `Child`. У вложенных компонентов действует та же структура папок.

Пример расположения слоёв (схема, а не текущее дерево файлов):

```text
src/
├── App/
│   └── SearchPage/
│       ├── SearchPage.tsx
│       ├── SearchPage.module.css
│       └── logic/
│           ├── useSearchPage.ts
│           └── tasks/
│               └── searchShows.ts
└── tasks/
    └── logout.ts
```

## Пример компонента

Абстрактный компонент, не из проекта:

```text
Counter/
├── Counter.tsx
├── Counter.module.css
├── types.ts
└── logic/
    └── useCounter.ts
```

`types.ts`:

```ts
export interface Props {
    className?: string;
    initialValue: number;
    onChange: (value: number) => void;
}
```

`Counter.tsx`:

```tsx
import clsx from 'clsx';

import type {Props} from './types';
import {useCounter} from './logic/useCounter';

import styles from './Counter.module.css';

export const Counter = (props: Props) => {
    const {className} = props;

    const {value, handleIncrement} = useCounter(props);

    return (
        <div className={clsx(styles.root, className)}>
            <span>{value}</span>
            <button type="button" onClick={handleIncrement}>
                +1
            </button>
        </div>
    );
};
```

`logic/useCounter.ts`:

```ts
import {useState} from 'react';

import type {Props} from '../types';

export const useCounter = (props: Props) => {
    const {initialValue, onChange} = props;

    const [value, setValue] = useState(initialValue);

    const handleIncrement = () => {
        const nextValue = value + 1;

        setValue(nextValue);
        onChange(nextValue);
    };

    return {value, handleIncrement};
};
```
